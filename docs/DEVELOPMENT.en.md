## Prerequisites

- These commands target macOS 12 or later and build a universal Apple silicon and Intel app; native builds on other hosts are outside this guide's scope.
- Install Go 1.26, Node.js 24, Xcode Command Line Tools, CMake, and Python 3.10 or later; ensure `go`, `node`, `npm`, `cmake`, and `python3` are on `PATH`. Building libmpv downloads sources and tools and requires network access.
- Install the pinned Wails CLI and add `$(go env GOPATH)/bin` to `PATH`. Although `make app-go` uses Go to build, its frontend target still needs `wails3` to generate bindings.
- Keep signing private keys only in protected files outside the repository or in release-environment secrets; never commit them.

From the repository root (follow the prompts to install Xcode Command Line Tools if needed):

```sh
xcode-select --install
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.28
export PATH="$(go env GOPATH)/bin:$PATH"
cd frontend && npm ci && cd ..
make app-go
```

`make app-go` generates bindings, builds the frontend, and produces `bin/pkp` and `bin/pkp.app`. The bundle includes `Contents/Helpers/pkp-updater`, a standalone macOS 12+ universal update helper built with Xcode's `swiftc`. Before running `./bin/pkp` directly, quit any older PKP instance that is already open; in-place updating requires an installed `.app`.

The Go module is `github.com/tonyflux/pkp`. Frontend bindings are in `frontend/bindings/github.com/tonyflux/pkp/` and are generated by Wails; do not edit them manually.

Run `make test` for the Go and frontend unit tests; `make dev` starts Wails development mode with hot reload.

AI subtitle decoding on macOS uses FFmpeg headers and dynamic libraries already exported by the libmpv build; the installed application does not need an `ffmpeg` executable. Decoder regressions use that executable to generate local synthetic fixtures. The app discovers subtitle nodes through PikPak at `https://api-drive.mypikpak.com` only after the user enables the feature. For isolated development, set `PKP_SUBSRELAY_API=http://127.0.0.1:<port>`; an explicitly empty value disables it. Custom endpoints may receive account tokens and audio, so do not use untrusted services; URL Basic Auth can replace the account token. Audio decoding currently requires Darwin+cgo, and other platforms hide the subtitle option.

Account-authenticated deployments check membership with the playing account and gate nonmembers in both frontend and backend. URL Basic Auth development deployments skip PikPak membership gating and leave eligibility to that deployment. `AISubtitleState.quota` retains the latest server snapshot for the same account; `known` distinguishes unknown from a real zero allowance. `limit`/`usage` are seconds and `nextResetTime` is RFC 3339. Showing quota while off does not request a node, and obsolete or cancelled sessions cannot overwrite newer state.

HTTPS subtitle deployments require encrypted nodes. Discovery and WebSocket handshakes reject redirects to plaintext; local plaintext services require an explicitly configured HTTP development address.

To verify the macOS update helper:

```sh
python3 build/darwin/updater-protocol-test.py bin/pkp-updater
python3 build/darwin/updater-smoke-test.py bin/pkp-updater
```

The first command launches no applications. The second needs a logged-in macOS desktop and uses isolated, signed, windowless fixtures to mount DMGs, replace apps, relaunch, and roll back. It never launches the real PKP or reads real account configuration. System replacement authorization approval/cancellation, the real app's quit confirmation, and Gatekeeper still require manual acceptance. Helper logs and receipts live in the current profile's user cache under `pkp/updates/<profile digest>/`; uncertain rollback retains the old-app backup and records its location in `install.log`.

## Windows cross-compilation

On the macOS host above, `make windows` builds x64 and ARM64 executables; these do not include the runtime libmpv DLL. `make windows-installer` packages the DLLs in an installer and additionally requires NSIS (`makensis` on `PATH`). The DLL build downloads a pinned macOS llvm-mingw toolchain and sources, and needs the CMake, Python, and network access listed above. This is not a guide to native Windows builds.

## Repository language

Use English for code comments, developer diagnostics, build output, internal model instructions, and non-localized administration pages. Public guides have linked English and Simplified Chinese versions.

Keep application copy in the existing translation system: `t` / `N_` in the frontend and `internal/i18n` in Go use Simplified Chinese source keys. Model instructions are English, but explicitly request replies in the selected interface language.

Chinese input grammars, Chinese naming presets, native language names, canonical persisted path labels, and fixtures that exercise Unicode or localized behavior are language data, not prose to translate. Changing them would remove language support or alter saved-data interpretation. Historical v0.1.0 legal terms and screenshots of the Chinese interface remain unchanged. Do not add scan suppressions to conceal non-translation prose.


## Release Materials

The first line of user-facing release notes must be `# PKP <version>`. Run the following from the repository root:

```sh
make release-local RELEASE_NOTES=build/release-notes.md
make release-verify
```

This only generates eight assets locally; it does not upload them: two installers, `update.json`, `update.json.sig`, `PKP-<version>-source.tar.gz`, `libmpv-sources.tar.gz`, `LICENSE`, and `SHA256SUMS`. The PKP-owned source archive must contain the complete corresponding source and build scripts used for that version's installers; third-party corresponding source is provided separately. v0.2.0 is published on GitHub Releases (2026-11-01) with those eight assets. macOS builds remain ad hoc signed, notarization is still absent, and device acceptance is incomplete. Signing keys must not be committed or written to logs.
