## Prerequisites

- The quick-start commands below target macOS 12+ and build a universal Apple silicon/Intel app; Linux has a separate section below.
- Install Go 1.26, Node.js 24, Xcode Command Line Tools, CMake, and Python 3.10 or later; ensure `go`, `node`, `npm`, `cmake`, and `python3` are on `PATH`. Building libmpv downloads sources and tools and requires network access.
- Install the pinned Wails CLI and add `$(go env GOPATH)/bin` to `PATH`. Although `make app-go` uses Go to build, its frontend target still needs `wails3` to generate bindings.
- Keep signing private keys only in protected files outside the repository or in release-environment secrets; never commit them.

From the repository root (follow the prompts to install Xcode Command Line Tools if needed):

```sh
xcode-select --install
go install github.com/wailsapp/wails/v3/cmd/wails3@v3.0.0-beta.28
export PATH="$(go env GOPATH)/bin:$PATH"
cd frontend && npm ci && cd ..
make app-go
```

`make app-go` generates bindings, builds the frontend, and produces `bin/pkp` and `bin/pkp.app`. The bundle includes `Contents/Helpers/pkp-updater`, a standalone macOS 12+ universal update helper built with Xcode's `swiftc`. Before running `./bin/pkp` directly, quit any older PKP instance that is already open; in-place updating requires an installed `.app`.

The Go module is `github.com/tonyflux/pkp`. Frontend bindings are in `frontend/bindings/github.com/tonyflux/pkp/` and are generated by Wails; do not edit them manually.

Run `make test` for the Go and frontend unit tests; `make dev` starts Wails development mode with hot reload.

The crash-feedback receiver lives in `cloudflare/telemetry`. Run `npm ci && npm run dev` there and start a desktop development build with `PKP_CRASH_API=http://127.0.0.1:8788`, using isolated test reports. Server builds never read host crash logs. Before release, run `npm run deploy` in that directory to apply D1 migrations and deploy both collection and admin Workers; verify that Cloudflare Access is actually enabled on the admin Worker and the daily cron is active. Developers review or delete reports at `https://pkp-telemetry-admin.pkpapp.cc/crashes`. App release does not deploy either Worker; an undeployed or unavailable receiver leaves sends failed and available for manual retry.

AI subtitles share the same FFmpeg audio-decoder source on macOS and Windows. macOS uses headers and dynamic libraries already exported by the libmpv build. For Windows x64/ARM64, the pinned toolchain links that source with static FFmpeg as `pkp-pcm.dll`, installed beside `pkp.exe` and loaded by the non-cgo Go binary using an absolute path, never the working directory or PATH. Production decoding does not launch an `ffmpeg` subprocess or require user-installed tools; decoder regressions use that command to generate local synthetic fixtures. The app discovers subtitle nodes through PikPak at `https://api-drive.mypikpak.com` only after the user enables the feature. For isolated development, set `PKP_SUBSRELAY_API=http://127.0.0.1:<port>`; an explicitly empty value disables it. Custom endpoints may receive account tokens and audio, so do not use untrusted services; URL Basic Auth can replace the account token. Other platforms without an audio decoder hide the subtitle option.

Account-authenticated deployments check membership with the playing account and gate nonmembers in both frontend and backend. URL Basic Auth development deployments skip PikPak membership gating and leave eligibility to that deployment. `AISubtitleState.quota` retains the latest server snapshot for the same account; `known` distinguishes unknown from a real zero allowance. `limit`/`usage` are seconds and `nextResetTime` is RFC 3339. Showing quota while off does not request a node, and obsolete or cancelled sessions cannot overwrite newer state.

HTTPS subtitle deployments require encrypted nodes. Discovery and WebSocket handshakes reject redirects to plaintext; local plaintext services require an explicitly configured HTTP development address.

To verify the macOS update helper:

```sh
python3 build/darwin/updater-protocol-test.py bin/pkp-updater
python3 build/darwin/updater-smoke-test.py bin/pkp-updater
```

The first command launches no applications. The second needs a logged-in macOS desktop and uses isolated, signed, windowless fixtures to mount DMGs, replace apps, relaunch, and roll back. It never launches the real PKP or reads real account configuration. System replacement authorization approval/cancellation, the real app's quit confirmation, and Gatekeeper still require manual acceptance. Helper logs and receipts live in the current profile's user cache under `pkp/updates/<profile digest>/`; uncertain rollback retains the old-app backup and records its location in `install.log`.

## Windows cross-compilation

On the macOS host above, `make windows` builds x64 and ARM64 executables; these do not include the runtime `libmpv-2.dll` or `pkp-pcm.dll`. `make windows-installer` packages the matching DLLs in an installer and additionally requires NSIS (`makensis` on PATH). The DLL build downloads a pinned macOS llvm-mingw toolchain and sources, and needs the CMake, Python, and network access listed above. This is not a guide to native Windows builds. To run a Windows binary or decoder tests manually, place `build/windows/libmpv/<arch>/pkp-pcm.dll` of the same architecture beside the executable; decoder tests also need `ffmpeg` on PATH to generate fixtures (the sibling `ffmpeg.exe` works directly).

CI reuses the macOS-built artifacts to run the same PCM timeline, audio-track, seeking and cancellation-recovery tests plus subtitle session, membership and quota integration tests on Windows x64 and ARM64. Compatibility-layer execution does not replace real-device player UI or installation/upgrade acceptance.

## Linux builds

Use native x86_64/ARM64 Ubuntu 24.04 or a matching-architecture container from `build/docker/Dockerfile.linux`; setting `GOOS` alone cannot replace CGO/system headers. Install Go 1.26, Node.js 24, the pinned Wails CLI and nFPM v2.43.0. The Dockerfile lists system build dependencies, including GTK4, WebKitGTK 6.0, libmpv, FFmpeg and libepoxy. Then run:

```sh
npm --prefix frontend ci
make linux-package ARCH=arm64
# Use ARCH=amd64 on x86_64; build other architectures inside a matching container.
```

Outputs are `bin/PKP-<version>-linux-<arch>.deb`, `.rpm`, `.AppImage`, and `-runtime-sources.tar.gz`. Deb uses distribution dependencies. RPM and AppImage include WebKit child processes, resources and the dynamic-library closure; a user namespace preserves compiled `/usr` paths without disabling the sandbox. Enable Ubuntu `deb-src` and retain APT indexes: packaging downloads exact corresponding sources and notices for the packages actually bundled. The pinned macOS/Windows media-source archive is not a substitute.

For a release, build each architecture from the same clean committed snapshot and run `make linux-provenance ARCH=<arch>`; use `make linux-docker-provenance ARCH=<arch>` inside the container workflow. The provenance check compares the deb, rpm and AppImage executable revision and matches the bundled runtime to its source archive. Old or modified packages cannot be used for release. Ordinary development builds allow uncommitted changes but cannot be released. The provenance file prevents accidental mixing; it is not a signature against deliberate forgery.

```sh
go test ./internal/mpv ./internal/pcm ./internal/audiotags ./internal/lanmedia
PKP_TEST_VIDEO_SURFACE=1 xvfb-run -a go test -tags pkp_surface_test ./internal/mpv -run TestLinuxSurface -count=1
```

Run the same surface test under headless Weston for Wayland. CI checks frame pixels, capture and window reparenting on both protocols. Real GNOME/KDE keyrings, polkit, notifications, GPU drivers, power management and installation/upgrades still require desktop acceptance. Use an isolated `PKP_CONFIG_DIR`, never real account state. Linux AI subtitles share `internal/pcm/decoder.c` and link FFmpeg through pkg-config without decoder subprocesses. LAN compatibility copies use absolute system `/usr/bin/ffmpeg`/`ffprobe` or private AppImage tools, never CWD/PATH discovery; Linux H.264 encoding uses the distribution's libx264.

The Linux filesystem trust boundary uses pinned directory descriptors, statx/filesystem identities and no-follow operations. Recursive inotify changes trigger revalidation and queue overflow causes a rescan. Ordinary ext4, XFS, Btrfs and tmpfs are supported; unrepresentable network/FUSE/overlay or directory-folding semantics are refused. Container CI mounts tmpfs `/tmp` so existing safety regressions execute rather than skip as unsupported. Unavailable Trash fails explicitly without permanent deletion.

Linux 6.8 may preserve ctime/mtime across immediate same-size writes, so timestamps cannot authorize reuse of a cached content hash. Linux versions therefore include a content digest, reused within the operation and read again for stability verification. Large media scans still incur two content passes; do not hide this limit with delayed tests or weaker identity checks.

Persistent LAN file tokens also fingerprint contents once for validation. Streaming checks a pinned-descriptor inotify proof before and after reads; writes, attribute changes or event overflow revoke it without rehashing an entire video for every network buffer.

## Repository language

Use English for code comments, developer diagnostics, build output, internal model instructions, and non-localized administration pages. Public guides have linked English and Simplified Chinese versions.

Keep application copy in the existing translation system: `t` / `N_` in the frontend and `internal/i18n` in Go use Simplified Chinese source keys. Model instructions are English, but explicitly request replies in the selected interface language.

Chinese input grammars, Chinese naming presets, native language names, canonical persisted path labels, and fixtures that exercise Unicode or localized behavior are language data, not prose to translate. Changing them would remove language support or alter saved-data interpretation. Historical v0.1.0 legal terms and screenshots of the Chinese interface remain unchanged. Do not add scan suppressions to conceal non-translation prose.


## Release Materials

The first line of user-facing release notes must be `# PKP <version>`. Run the following from the repository root:

```sh
make release-local RELEASE_NOTES=build/release-notes.md
make release-verify
```

Historical eight-asset releases remain verifiable. A Linux-inclusive release adds six packages and two per-architecture runtime-source archives, for sixteen assets. The signed manifest keeps the two legacy `packages` entries and authenticates additions in `linuxPackages`, preserving older clients. On the macOS signing host, supply `LINUX_RELEASE_DIR=/path/to/Linux/assets/from/the/same/source` to assemble both architectures. Commit a clean source snapshot before release. Building/signing does not upload or complete device acceptance/Apple notarization. Never commit signing keys or print them in logs.
